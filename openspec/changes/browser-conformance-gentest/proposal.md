## Why

The project's ground truth is currently a snapshot of Taffy's generated XML fixtures, pinned to a Taffy commit — so our ceiling is "matches Taffy's Chrome-from-whenever", we cannot author new test cases, and we cannot detect where Taffy itself diverges from browsers. The priority going forward is conformance with real browsers and the CSS specs, not Taffy parity. Taffy's own fixtures were generated from Chrome via a WebDriver pipeline (`scripts/gentest`), so the shortest path is to bring that generator in-repo — TypeScript + Puppeteer — and make a pinned real Chrome the direct source of truth.

## What Changes

- Vendor the *source* fixture corpus: Taffy's `test_fixtures/{flex,block,blockflex,blockgrid,grid,gridflex}` HTML files (1,105 files, MIT), plus `test_helper.js` (in-page style/layout extractor, reused nearly verbatim), `test_base_style.css`, and the Ahem font it embeds.
- New `scripts/gentest.ts`: a Puppeteer driver that loads each HTML fixture in pinned headless Chrome, invokes the in-page helper to produce the four variant descriptions (border/content-box × ltr/rtl), and serializes them to the same XML fixture format the vitest harness already consumes (porting the XML-writer half of Taffy's Rust driver). Run via `pnpm gentest [pattern]`.
- Regenerate all XML fixtures from our own Chrome and reconcile against the vendored Taffy XML. Divergence policy: **the browser wins** — where fresh Chrome disagrees with Taffy's old snapshot, adopt the browser expectation and fix the engine if it then fails. Record the Chrome version as fixture provenance (replacing the Taffy commit pin as the authority).
- Establish the authoring loop away from Taffy: write HTML → `pnpm gentest` → committed XML → `pnpm test`, documented in the README; prove it with a first batch of new HTML fixtures covering spec cases absent from Taffy's corpus.
- The test suite stays hermetic: generated XML is committed and `pnpm test` never launches a browser; Puppeteer runs only at fixture-generation time.
- Out of scope: WPT (Web Platform Tests) integration, cross-browser generation (Firefox/Safari), fuzzing, visual/screenshot testing. Single pinned Chrome is the reference for now.

## Capabilities

### New Capabilities

- `browser-fixture-generation`: Generating conformance fixtures from a real, pinned browser — loading HTML fixture files in headless Chrome, extracting input styles and expected layouts (including all box-sizing/direction variants and Ahem-font text), and emitting the harness's XML format deterministically.

### Modified Capabilities

- `conformance-harness`: The "Pinned fixture provenance" requirement changes — fixtures SHALL be generated by the in-repo browser pipeline with a recorded Chrome version as their provenance, and regeneration SHALL be reproducible, replacing verbatim-copy-from-Taffy provenance.

## Impact

- New: `scripts/gentest.ts`, vendored `tests/html/**` (HTML corpus + helper JS/CSS/font), `tests/fixtures/CHROME_VERSION`.
- Modified: regenerated `tests/fixtures/**/*.xml` (expect a small diff where current Chrome disagrees with Taffy's snapshot — each is triaged, and engine fixes may fall out), README (conformance + authoring docs), package.json (`gentest` script, `puppeteer` dev-dependency — dev-time only, the published package is unaffected).
- The Taffy clone stops being needed for fixtures; it remains only as an algorithm reference for `src/compute/` sync.
